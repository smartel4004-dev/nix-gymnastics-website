# NIX Gymnastics — website

Static site: HTML, one stylesheet, one small vanilla JS file. No framework or build tooling beyond a tiny Python script that shares the header, menu and footer across pages.

## Run it

```bash
cd site && python3 build.py          # rebuild pages from _pages/
python3 -m http.server 8417 --directory site
```

Edit page content in `_pages/*.html`, never the generated `*.html` files in `site/`. Shared header, menu, footer and phone/email live in `build.py`.

**Primary action everywhere:** "Book a free trial class" → `contact.html`. Links can preselect the form: `contact.html?type=team`, `?type=party`, `?program=tumbling` (values match the program `<select>`).

## Team meets, results & news

Meets live in `_data/meets.json`, one entry per meet:

```json
{"name": "Frederick Flips", "start": "2027-02-13", "end": "2027-02-13", "squad": "boys",
 "host": "USA Gymnastics", "host_url": "https://usagym.org",
 "venue": "Springfield College", "street": "263 Alden St", "city": "Springfield", "state": "MA", "zip": "01109"}
```

`squad` is `boys` or `girls`. Leave `venue`/`host_url` empty if unknown. Run `python3 build.py`: it rebuilds the calendar, the Team page preview and the `.ics` files in `assets/cal/` (one per meet plus `nix-team-meets.ics` for the whole upcoming season). The page also re-checks dates in the browser, so a finished meet moves to "Past meets" even if nobody rebuilds.

Results and news live in `_data/news.json` (`date` as `YYYY`, `YYYY-MM` or `YYYY-MM-DD`; `kind` is `result` or `news`; optional `link` and `scoreboard`). See the 2016 New England Championships entry for the scoreboard format.

The registration form is `assets/docs/nix-registration-form.pdf` (copied from the current site's `childregistrform.pdf`). Replace the file to update it everywhere: Programs, Contact and the footer.

## Photo galleries

A gallery is entered **once**, in `_data/galleries.json`, and linked to a meet by the meet's id (`"event": "friendship-classic-2026"`, the same id as in `meets.html#friendship-classic-2026`). Its title, dates, season, team and venue all come from the meet. From that one record the build produces:

- the gallery's own page (`gallery-<id>.html`)
- its card on `galleries.html` (season + team filters)
- a "Photos (n)" link on the meet in the calendar (upcoming or past)
- a "See the photos" link on any news post with the same `"event"`

To add one:

```bash
python3 tools/gallery_import.py <meet-id> ~/Pictures/meet/*.jpg   # resizes to 1600px + 640px thumbs
# then fill in each photo's "alt" (and "credit", "cover") in _data/galleries.json
python3 build.py
```

A gallery that isn't a meet (an open house, say) leaves `"event"` empty and sets `"title"`, `"date"`, optional `"end"`, `"squad"` and `"where"` itself.

### Moving to a CMS

Keep the same three content types and the reference between them; the templates don't change.

| Type | Fields |
|---|---|
| **Meet** | name, start, end, team (boys/girls), host, host URL, venue, address |
| **Gallery** | meet (reference, optional), title/date/team (only when there's no meet), cover photo, credit, photos[] |
| **Photo** (inside a gallery) | image, alt text (required), caption (optional) |
| **News post** | date, kind (result/news), title, body, link, scoreboard, meet (reference, optional) |

Recommendation: build the CMS version on **WordPress** (the gym already runs it) as a custom theme with custom post types for Meet, Gallery and News, an ACF relationship field from Gallery/News to Meet, and the media library for uploads (it creates the responsive sizes this build makes with `tools/`). If the site moves to static hosting instead, **Sanity** fits the model best (references are first-class, and its image CDN handles sizes and crops). A Git-based CMS such as Decap is a poor fit for galleries: hundreds of meet photos would live in the repository.

The lightbox is **PhotoSwipe 5.4.4** (MIT), vendored in `assets/vendor/photoswipe/`; it works with any of these.

## Design system (in `assets/css/styles.css`)

- **Type:** Archivo (variable width; headlines at 62% width, uppercase) + Hanken Grotesk for body text. One italic "leap" word per headline (`.leap`) echoes the leaping figure in the logo.
- **Color:** ink `#0f1512`, NIX green `#1d7f57` (from the logo), deep green `#146142` for text on light, green tint `#69d3a8` (logo hue, lighter) only on dark surfaces, warm paper `#f4f2ec`. All text pairs meet WCAG AA.
- **Motif:** the leap diagonal is used for section cuts (`.cut-top`, `.cut-bottom`), the corner notch on buttons and images (`.img--notch`) and a single tint speed line in the hero.
- **Components:** `.btn` (+ `--tint`, `--white`, `--ink`, `--lg`, `--sm`), `.link-arrow` for secondary actions, `.checks`, `.schedule`, `.facts`, `.steps`, `.path`, `.timeline`.
- **Motion:** fade-up reveals, a gentle hero image settle, a finder hover preview (mouse/trackpad only). Everything is disabled under `prefers-reduced-motion`.
- **Breakpoints:** 1100 / 1000 / 960 (nav → menu) / 860 / 760 (phone layouts + sticky action bar) / 600.
